# GPT CDK自助充值：Windows 单 EXE 方案

状态：待用户确认；尚未生成 Windows 产物。

## 目标和选择

将当前工作区的 Vue 页面、Go 服务和 SQLite 支持打包为 Windows x64 可执行文件，保留品牌名“GPT CDK自助充值”。首版目标为 Windows 10/11 x64，不包含 Windows ARM64、macOS 应用或公网部署。

采用单 EXE 自动打开默认浏览器的方案。对比：安装向导适合快捷方式与卸载管理，但需要额外打包流程；内置桌面窗口需要额外窗口框架和运行时。本次不引入这两项。

## 交付与启动

- 交付 `GPT-CDK-windows-amd64.exe`、中文使用说明和 SHA-256 校验文件；EXE 无需安装 Go、Node、Docker、PostgreSQL 或 Redis。
- 使用独立便携入口，保留现有 Docker 的服务入口与启动方式。
- 前端生产资源通过 Go embed 内嵌；不包含源码映射、现有数据库、Session、API Key、密码或环境配置文件。
- 仅监听 127.0.0.1；优先使用 8081，端口占用时选择可用本机端口，不终止占用端口的其他程序。
- 健康检查成功后打开默认浏览器。首次访问进入现有管理员初始化流程，之后进入首页；用户自己设置管理员凭证及上游配置。
- 首版保留控制台窗口用于显示访问地址和退出提示；浏览器关闭不会结束服务，通过 Ctrl+C 停止。优雅关闭 HTTP 服务与数据库。
- 使用 Windows 命名互斥量限制同一用户重复运行；重复启动显示明确提示，不并发启动第二个写数据库的服务。

## 数据和安全边界

- 数据放在当前用户的 `%LOCALAPPDATA%\GPT-CDK\`，包含 SQLite 数据库和独立随机 JWT 密钥，不写入 EXE 本体。
- 首次生成强随机密钥，后续复用；密钥不输出到日志。初始化失败时清楚报错，不使用开发默认密钥继续启动。
- 升级只替换已退出的 EXE，保留数据目录。不会自动导入当前 Mac Docker 数据卷。
- 不修改当前运行的 Docker 容器、数据卷、管理员密码或上游设置。
- 发码与充值仍然依赖外部卡台联网服务；单机打包不等于离线支付。
- 本次不顺带修复此前审查发现的业务漏洞。交付说明必须明确这些风险尚未消除，不将产物描述为已完成资金安全加固。

## 必须的兼容改动

- 把更新模块中的 syscall.Exec 等平台相关代码拆分到平台文件，Windows 不编译 Linux 实现。
- Windows 版禁用 Linux 一键热更新，并显示不支持原因；使用退出程序后手动替换 EXE 的升级方式。
- 保留当前 SQLite 驱动，通过 Windows C 交叉编译工具链构建；检查 PE 架构及 DLL 导入，确保不依赖额外第三方 DLL。若不能满足，先明确缺失项，不把需外部 DLL 的产物称为单文件免环境版。
- 前端资源路由保持已有 API 路由与 SPA 回退边界；找不到 API 时返回404，不返回首页冒充接口响应。

## 构建与验收

- 本机是 macOS，已发现 Go，但 PATH 中未发现 MinGW、Zig 或 Wine。构建阶段需要获取经核验的交叉编译工具，或使用 Windows 构建环境；不自动创建远端仓库或上传代码。
- 先测试资源路由、数据目录/密钥初始化、错误处理及重复启动边界，再实施平台适配。
- 构建前端、运行聚焦 Go 测试、构建 Windows x64 EXE、检查文件格式/DLL依赖和内嵌品牌名称，输出校验和。
- 保留原 Docker 构建兼容性，但不自动重新部署 Docker。
- Windows 原生验收包括首次启动、管理员初始化、重启保留数据、端口占用、重复启动、退出后重新打开以及路径含空格/中文。
- 如果本机没有可用 Windows 运行环境，必须在交付中区分“交叉编译与静态检查通过”和“Windows 实机运行验证”，不能宣称未执行的测试已通过。
